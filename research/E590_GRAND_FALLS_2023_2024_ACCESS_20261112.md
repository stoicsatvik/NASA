## Question

Can the distinct USGS Grand Falls Dune Field July 2023–November 2024 release provide a small, anonymous, provenance-pinned field-data sample that advances an Earth-side aeolian reference beyond the earlier 2017–2019 access attempt?

This is a different data period and release from E577, not a guessed URL variant or retry of E577's item.

- Data.gov/USGS catalog identifier: `USGS:67bf94acd34e8876fcbfc91b`
- USGS catalog states public access and CC0 1.0. The Data.gov mirror says no license information was provided; use the primary USGS release's stated terms and preserve its citation.
- Published coverage: 7 July 2023–18 November 2024. The release describes sediment flux, meteorology, imagery, photogrammetry, DEMs and orthomosaics at the Grand Falls Dune Field.
- The site is on the Navajo Nation. This probe uses existing public research data only; it does not authorize field access, sampling or contact.

## Why this source matters

The release describes barchans, dome dunes, smaller dunes and ripples, with bimodal grain composition. It may provide measured Earth-side morphology, surface change and meteorological context that can be compared with the Mars-side MGD3/CTX/HiRISE evidence. It is a separate release from E577 but the same geographic site, not independent-site replication.

## Frozen acquisition protocol

- Anonymous HTTPS only; no credentials, cookies, API keys, accounts, contact or access-control bypass.
- Bounded metadata requests only to the DOI parent, its documented immediate-child search, and the exact Data.gov catalog identifier. Each request is capped at 5 MB and 20 seconds.
- Inspect both top-level `files` and ScienceBase `facets.files`; the official ScienceBase Python client documents both locations.
- Record only file names, sizes, extensions and redacted host/query-key summaries.
- Select at most one metadata-listed CSV/TXT/TSV/DAT/ZIP no larger than 5 MB for full acquisition.
- Permit at most two 4 KiB range probes only when the first metadata-listed candidate returns an HTML/error response; never repeat the same URL.
- Prefer an explicit ScienceBase `www.sciencebase.gov/catalog/file/get/?f=...` file endpoint over a smaller `sciencebase.usgs.gov` page URL.
- Require HTTP 206, non-HTML content type and exact Content-Range/catalogue-size agreement before the one full bounded read.
- Preserve only byte counts, SHA-256, schema/row/time summaries and aggregate wind/sediment/temperature/pressure statistics.
- No raw field rows, raw file bytes, full URLs, signed query values, coordinates, images or DEMs are committed or uploaded.
- If no small admissible file exists, preserve the inventory and stop; do not guess URLs or bypass access restrictions.

## First exact-head observation

The initial implementation queried the DOI parent and Data.gov catalog identifier, but inspected only top-level `files`. Both metadata requests returned HTTP 200 with zero top-level file records. That is **not** a source-absence result: ScienceBase also exposes files through facets and organizes records into parent/child item hierarchies. The corrected probe inspects both file locations and the documented parent-child relation before making an access decision.

## Exact-head observations

1. The first implementation saw HTTP 200 but zero top-level file records. It did not inspect `facets.files` or parent/child items; this was an implementation gap, not evidence of source absence.
2. The corrected hierarchy/facet probe returned HTTP 200 for the DOI parent, child search and Data.gov catalog item. It found five child items and five file records. The catalog identifier was confirmed in the parent's child list.
3. The smallest CSV candidate (`SensorData_02-14-24_to_02-16-24.csv`, 1,091,813 bytes) did **not** pass the transfer gate: HTTP 206 was returned, but the response was HTML and its Content-Range total was 4,255 bytes, not the catalogue size. No field rows were acquired or profiled.
4. A second metadata-listed CSV (`SensorData_11-12-24_to_11-18-24.csv`, 3,319,414 bytes) uses a distinct explicit `www.sciencebase.gov` file URL with an `f` selector. The next bounded probe prefers that URL. It is a different file/endpoint, not a retry of the failed URL.
